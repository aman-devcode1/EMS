Professional Layer-by-Layer Flow (Dependencies kaun kis par)
Dhyaan rakhein: Dependency hamesha Andar ki taraf jaati hai (Outside -> Inside).

EMS.Core (Foundation) -> Kisiko reference nahi karta.

EMS.Infrastructure (Construction Material) -> Sirf Core ko reference karta hai. (DbContext, Repository yahan banate hain).

EMS.Services (Plumbing / Electricity logic) -> Infrastructure aur Core dono ko reference karta hai. (AutoMapper, Business Rules yahan).

EMS.API (Building ka Gate / Entrance) -> Sirf Services ko reference karta hai. (Controllers, Middlewares yahan).

Jab koi naya project dega toh mere dimaag mein step-by-step kaisa map banega?

Step 1 (Pehle kya bane?): EMS.Core
➡️ Sabse pehle Entities (tables) sochiye. Phir DTOs (client ko kya data bhejna hai?). Phir Interfaces (Repositories aur Services ke contracts).

Step 2 (Doosre kya bane?): EMS.Infrastructure
➡️ DbContext banayein, connection string configure karein, aur Core ki Interfaces ko implement karte hue Repositories likhein. Migrations yahan run karein.

Step 3 (Teesre kya bane?): EMS.Services
➡️ AutoMapper Profiles banayein. Core ki Service Interface ko implement karte hue actual Service class likhein. Isme Repository call karein, mapping karein, aur business logic (validation, calculations) daalein.

Step 4 (Chautha kya bane?): EMS.API
➡️ Program.cs (Dependency Injection register karna), Controllers (Endpoints banana), aur Middlewares (Exception handling, Logging, JWT) yahan banayein.

Depend karna (Reference): API -> Services -> Infrastructure -> Core. (Core sabse neeche, API sabse upar).


==> 
Aakhri Gyan (The Golden Rule of Professional Coding):
Jab bhi aap kuch likhein, apne aap se poochhiye:
Kya yeh logic har jagah change ho sakta hai? -> Use Service.
Kya yeh sirf database se related hai? -> Use Repository (Infrastructure).
Kya yeh client (Angular) ko bhejna hai? -> Use DTO (Core).
Kya yeh har request ke aane jaane par check hona chahiye? -> Use Middleware (API).

Kha Kyab Hota Hai...

1. Interface = एक अनुबंध (Contract) जिसमें मेथड के नाम, पैरामीटर और रिटर्न टाइप लिखे होते हैं — न कोई बॉडी, न कोई लॉजिक।

2. Repository : a. yeh Interface par depend karta hai.
                b. यह वह जगह है जहाँ हम डेटाबेस से बात करने का सारा कोड लिखते हैं।
                c. यहाँ Entity Framework Core (DbContext) का इस्तेमाल होता है।
                d. LINQ क्वेरीज़, SQL कॉल, या कोई और डेटा एक्सेस लॉजिक रहता है।
                e. इंटरफ़ेस में जो मेथड सिर्फ़ घोषित (declare) हुआ था, उसकी बॉडी यहाँ लिखी जाती है — "काम कैसे होगा"। 

3. Service : वह कंज़्यूमर है जो इंटरफ़ेस के ज़रिए कहती है — “मुझे GetByIdAsync(5) दे दो” — और उसे बस रिज़ल्ट से मतलब है, तरीके से नहीं।
