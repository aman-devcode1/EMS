│   ├── DTOs/  Layer-2                  सरल भाषा: DTO एक "खाली डिब्बा (Empty Box)" है। इसमें सिर्फ Properties (गुण) होते हैं, कोई Logic (तर्क) नहीं होता (कोई Method नहीं, कोई Calculate नहीं)।          Technical Definition: यह एक Plain C# Class (POCO) है, जिसका एकमात्र काम एक Layer से दूसरी Layer तक Data को ले जाना (Transfer) है।
│   │   ├── EmployeeCreateDto.cs        जब Client (Frontend) कोई नया Employee Add (POST) करना चाहता है, तो वह इस डिब्बे में Data भरकर भेजता है।        Client को हमारी Database का CreatedAt, IsActive जैसे Internal (अंदरूनी) फील्ड्स नहीं दिखाने चाहिए। सिर्फ वही भेजो जो Client को भरना है।
│   │   ├── EmployeeResponseDto.cs      जब Server (Backend) Client को Employee का Data वापस (Response) भेजता है, तो यह डिब्बा Use होता है।       Client को हमारी Database की हर Property (जैसे PasswordHash, RowVersion) नहीं दिखानी चाहिए। हम सिर्फ वही दिखाते हैं जो UI को चाहिए।
│   │   ├── EmployeeQueryParams.cs      जब Client को "सिर्फ IT Department वाले, Active Employees, जिनके नाम में 'Raj' आता है" ढूंढने हों, तो वह इन Parameters को URL में भेजता है।      अगर 10,000 Employees हैं, तो एक साथ सारे नहीं भेज सकते। यह डिब्बा Client को यह बताने देता है कि "मुझे सिर्फ यही चाहिए"।
│   │   ├── LoginDto.cs                 जब User अपना Email और Password डालकर Login बटन दबाता है, तो यह डेटा Server तक आता है।     Login में सिर्फ इन 2 चीज़ों की जरूरत होती है। हमें FirstName या Department नहीं चाहिए।

│       ├── IEmployeeService.cs         Employee से जुड़े सारे Business Rules (व्यावसायिक नियम) का Contract।        Controller (API) को Direct Database Query नहीं पता होनी चाहिए। Controller बस कहेगा "Employee Add करो", Service जाकर चेक करेगा कि "क्या Duplicate Email तो नहीं?", "क्या Age 18+ है?", और फिर Repository को Call करेगा।      EMS.Services/Services/EmployeeService.cs mein ye impliment hoga।        AddEmployeeAsync(EmployeeCreateDto dto), GetEmployeesAsync(EmployeeQueryParams params), UpdateEmployeeAsync(int id, dto)। (ध्यान दें: Service DTO लेता है, सीधा Entity नहीं)।
│       └── IAuthService.cs             Authentication (लॉगिन/रजिस्टर) और Token Generation (JWT) का Contract।        Login और Register की Logic अलग होती है। इसमें Password Hashing, JWT Token बनाना, Refresh Token हैंडल करना शामिल है।       EMS.Services/Services/AuthService.cs mein ye impliment hoga।        LoginAsync(LoginDto dto), RegisterAsync(RegisterDto dto), GenerateTokenAsync(User user)।
